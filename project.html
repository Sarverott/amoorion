Getting started

pip install amoorion amoorion-bluesky        # the core and the platforms you use
amoorion                                     # asks step by step what to do
amoorion publish --text "hello" --to dryrun  # dryrun sends nothing: try it first

What it does

  • Publish: write once, post to every platform you name.
  • Read & reply: read what came in, in one inbox, and answer from there.
  • Keep: every profile's posts as JSON files in dataset/; delete keeps a copy of what it removes.
  • Connect: link the platforms with each other and with the services around them (webhooks, ntfy, NATS, e-mail: phase 5 of the plan).

How it is built

One core (model, view, controller) and namespaces on it: plugins (one per platform), methods (what amoorion can do), and the faces that expose the methods: CLI, HTTP API, MCP server for AI agents, and a daemon for long-running services. Secrets come only from a vault (Bitwarden / Vaultwarden, HashiCorp Vault / OpenBao, or a KeePassXC file); .env holds just the link to it. Each platform is its own package in packages/ (a uv workspace). Details: docs/structure.md, writing a plugin: docs/plugins.md.

Usage

uv sync
cp example.env .env                          # the link to the vault

uv run amoorion                              # asks step by step what to do (or: amoorion -i)
uv run amoorion plugins                      # platforms and what they can do
uv run amoorion accounts                     # which have their secrets in the vault
uv run amoorion publish --text "hello" --to dryrun bluesky
uv run amoorion --json read --platform bluesky
uv run amoorion reply --platform bluesky --to "at://…" --text "thanks"
uv run amoorion inbox                        # everything read or received so far
uv run amoorion snapshot --platform bluesky  # its posts into dataset/bluesky/<profile>/ (JSON, indexed)
uv run amoorion delete --platform bluesky --id "at://…"   # keeps a copy in the dataset first
uv run task help                             # help of every command

uv run amoorion api                          # HTTP API on 127.0.0.1:8000
uv run amoorion mcp                          # MCP server (stdio) for agents
uv run amoorion daemon                       # long-running services

The API needs the secret api/token in the vault (sent as Authorization: Bearer), and every hook its own secret; without them they refuse calls. Where each backend keeps a secret: docs/structure.md. Each platform's secrets are listed in its package's README, e.g. packages/amoorion-bluesky.

Run locally first; a Dockerfile and compose come next (phase 6 of the plan).

Development

uv run task init               # tools, git hooks, .env, then check
uv run task vault:new          # KeePassXC: the file of AMOORION_VAULT_PATH, an empty entry per platform
uv run task vault:status       # the vault's state, and which platforms have their secrets
uv run task vault:tools        # Bitwarden instead: bw by npm into tools/, then vault:login
uv run task check              # tests, YAML, commit messages, docs (= CI)
uv run task docs:build         # the docs site into docs/_build/html
uv run task plugin:new -- <platform> <Class> "<description>"   # a new platform
uv run task test:connect       # read-only: log in to every platform with its secrets, read a few posts
uv run task test:live          # a real test post on each (or: -- bluesky mastodon), read, replied, deleted

Examples of usage: Jupyter notebooks in examples/ (uv run task examples:build makes marimo notebooks and pages of them). The docs (this README, the guides, the plan and an API reference generated from the code) are built by Sphinx from docs/ for Read the Docs. Plan and open questions: docs/devlog/. Platforms

amoorion-blogger

Blogger plugin of amoorion: posts by e-mail to the blog's secret posting address (Blogger → Settings → Email → Post using email).

amoorion-bluesky

Bluesky plugin of amoorion: post (links and tags as clickable facets), read, reply and delete (only its own posts) through the AT Protocol.

amoorion-discord

Discord plugins of amoorion, both ways of decision Q12:

amoorion-email

E-mail plugin of amoorion: post (send to one address), read a mailbox and reply to the sender. Mail only ever goes encrypted.

amoorion-facebook

Facebook plugin of amoorion: post on a Facebook Page, read its posts, reply as comments, and delete posts or comments, through the Graph API.

amoorion-mastodon

Mastodon plugin of amoorion: post, read, reply and delete through the REST API of a Mastodon (or compatible) server.

amoorion-matrix

Matrix plugin of amoorion: posts, reads, replies and deletes (redacts) in one room through the client-server API of any homeserver.

amoorion-ntfy

ntfy plugin of amoorion: push notifications to one topic, and read what the topic holds. Also a notification target: set `AMOORION_NOTIFY=ntfy` in `.env` and everything the hooks receive is sent there too.

amoorion-telegram

Telegram plugin of amoorion: a bot posts, reads, replies and deletes in one chat (a group, a channel or a private chat) through the Bot API.

amoorion-tumblr

Tumblr plugin of amoorion: post, read and delete through the Tumblr API v2 (Neue Post Format), signed with OAuth 1.0a.

amoorion-x

X (twitter) plugin of amoorion: post, read, reply and delete through the X API v2, signed with OAuth 1.0a for the account itself.
